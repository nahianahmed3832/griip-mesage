| Connection | the SRV string (`mongodb+srv://…`, TLS by default), database `orbit` |
| Backups | Cloud Backup on, with a snapshot schedule and retention you choose (e.g. daily, 14 days) |

**Putting the URI on the VPS without it passing through chat** (the owner runs this on the VPS; it asks for the value
without echoing it and keeps a dated copy of the old `.env`):

```bash
cd /opt/griip-internal-messaging && cp -p .env ".env.pre-mongo-$(date -u +%Y%m%dT%H%M%SZ)" && read -rs -p "MongoDB URI: " U && printf '\nMONGODB_URI=%s\nMONGODB_DB=orbit\n' "$U" >> .env && unset U && chmod 600 .env && echo saved
```

API 0.4.2 ignores these lines, so adding them early changes nothing. `MONGODB_DOMAINS` stays unset until step 5.

## 3. Off-site encrypted backups ⛳

Today backups exist only on the VPS, unencrypted. Before any migration:

1. **Owner, on the Mac**: `age-keygen -o ~/orbit-backup-key.txt`, keep that file offline (password manager or paper);
   the printed `age1…` public key goes to the VPS. The VPS can encrypt to it but never decrypt.
2. ⛳ **AWS** (orbit-admin profile, never root): deploy `deploy/aws/orbit-backups.yaml` as stack `orbit-backups-prod` in
   ap-southeast-1 with `PermissionsBoundaryArn` = the `orbit-runtime-boundary` ARN and `--tags app=orbit env=prod`:
   bucket `griipbuddy-orbit-db-backups-sg` (versioned, object lock governance 14 days, 35-day expiry, TLS only, public
   access blocked) and user `orbit-api-backup-writer-prod` (PutObject only, from 72.60.107.88 only). Create its access key
   and pipe it straight into `/root/.orbit-offsite.env` (mode 600) on the VPS with `OFFSITE_BUCKET`,
   `OFFSITE_AGE_RECIPIENT` and an AWS credentials file; never shown.
3. ⛳ **VPS**: `apt-get install -y age awscli` (or the AWS CLI v2 installer), then first
   `bash scripts/offsite-backup.sh --label check --local /root/offsite-check` (the Docker path wasn't runnable on the
   Mac: only the encrypt and restore steps were rehearsed there), then `bash scripts/offsite-backup.sh --label pre-0-5-0`.
   Expected: "uploaded: s3://…/orbit-db/orbit-pre-0-5-0-<time>.tar.gz.age".
4. **Restore check on the Mac** (not production): download with `--profile orbit-admin`, then
   `bash deploy/scripts/offsite-restore-check.sh <file>.tar.gz.age <file>.manifest.json ~/orbit-backup-key.txt`
   (checksum, integrity, schema version, row counts per table; `--serve` starts a throwaway server on it).
   Rehearsed on 2026-10-19 with test data: passed; a wrong key can't decrypt.
5. ⛳ Daily schedule (root cron, e.g. 03:30 UTC): `bash /opt/griip-internal-messaging/scripts/offsite-backup.sh`.

## 5. Cutover window: accounts and preferences move to MongoDB ⛳ (about 10 minutes, announce to the team)

1. Write freeze: `docker compose -p griip-internal-messaging stop api` (phones keep their outboxes and retry).
2. `bash scripts/offsite-backup.sh --label pre-cutover` (with the API stopped it snapshots through a one-off API
   container, so nothing written before the freeze is missed).
3. `docker compose run --rm api node dist/admin.js table-counts` (record), then
   `… mongo-migrate accounts --yes` and `… mongo-migrate preferences --yes`. Each backs SQLite up first, copies, and
   switches the domain only if counts, ids, row hashes and checksums all match.
4. Add `MONGODB_DOMAINS=accounts,preferences` to `.env`; `docker compose up -d --no-deps api`.
5. Smoke tests: `/healthz` (mongodb true); `mongo-status` (both domains `mongodb`, counts equal to step 3); sign-in with
   a test account on the production server (never the owner's normal account), token refresh, workspace list,
   preferences write (Orbit Test pointed at production with a test account), a DM and a channel message, a call ring, a
   file download; an employee app that was signed in before keeps working (sessions moved). Error log: no 5xx.
6. If anything fails: rollback below, then investigate.

## 6. Observation (14 days)

Daily: `mongo-status` (counts, round trip), API error log (503 `unavailable` would mean MongoDB unreachable), Atlas
metrics and alerts, off-site backup success. SQLite keeps its frozen copy of the two domains untouched.

**Rollback after the switch** ⛳: stop the API; `docker compose run --rm api node dist/admin.js mongo-rollback accounts --yes`
and `… preferences --yes` (each backs SQLite up first and brings back everything written since the cutover, FK-checked);
remove `MONGODB_DOMAINS` from `.env`; start. Never start an older image before this step: it would serve SQLite's stale
copy. Rehearsed on the device-test server with phone-written data (Report B §6).
